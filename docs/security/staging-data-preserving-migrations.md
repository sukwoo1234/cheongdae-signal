# 스테이징 기존 행사 데이터 보존 마이그레이션

스테이징에는 0023까지 적용된 상태에서 참가자·카드·매칭 데이터가 남아 있다.
현재 앱은 0024 이후의 계정 칼럼과 RPC를 사용하므로, 스테이징 DB가 이전
버전에 머무르면 일반 사용자 로그인이 실패한다. 이 문서는 기존 행사 데이터를
삭제하지 않고 0024 이후로 올릴 때의 검증 조건을 기록한다.

0024의 기존 빈 데이터 조건은 운영 DB에 빈 회차에서 이미 적용된 뒤 제거했다.
수정한 0024는 기존 사용자와 행사 원장을 그대로 두고 `last_active_at`을
추가한다. 기존 계정의 `retention_accepted_at`은 `NULL`로 남겨 계정 보유
동의를 소급해서 간주하지 않는다. 따라서 이 계정들은 다음 행사 폐기 시
기존 정책대로 정리된다. 0025의 연락처 유형 채우기는 생성 칼럼을 일반
칼럼으로 바꾸는 방식으로 수행한다. 기존 카드의 `updated_at`과 매칭
기록을 바꾸는 행 단위 UPDATE가 발생하지 않는다.

운영 DB에는 수정 전 0024·0025가 이미 적용돼 있다. 같은 버전 번호의 파일
내용이 이후 변경됐으므로 마이그레이션 목록의 일치만으로 양쪽 DB 상태가
같다고 판단하면 안 된다. 이 수정은 기존 운영 DB에 재실행되지 않으며,
스테이징 적용 후 칼럼·함수·정책 상태를 운영 DB와 별도로 대조해야 한다.

스테이징 적용 전에는 복구 가능한 DB 백업을 확보하고, 원격 마이그레이션
목록이 0023에서 끝나는지, `session_config.purging`이 `false`인지,
Auth 계정·프로필·카드·매칭·참가 원장의 건수와 기존 칼럼 해시가 예상과
일치하는지 확인한다. 0025는 숫자 형식의 기존 연락처를 휴대전화로,
나머지를 종전 입력 안내에 따라 인스타그램으로 표시한다. 기존 값이
카카오톡 ID인지 자동으로 구분할 수 없으므로 이 유형 판단도 확인해야 한다.
개인 연락처 값은 로그나 테스트 결과에 출력하지 않는다.

로컬 PGlite의 `legacy-event-migration.test.ts`는 0023 상태에 합성
프로필 2건·카드 2건·매칭 1건을 넣은 뒤 0024–0028을 적용해 기존 값,
시각, 연결 관계와 비동의 상태가 유지되는지 검증한다. 원격 적용 후에도
동일한 기존 칼럼 해시·건수와 새 칼럼 상태를 재확인한다. 이 문서는
스테이징 데이터 삭제나 운영 DB 변경을 허용하는 절차가 아니다.
